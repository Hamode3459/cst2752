About this system

This portal was built as a university case study in secure web application design. It runs entirely in the browser using HTML5, CSS3 and vanilla JavaScript, with IndexedDB acting as the clinical database, populated from the module's JSON data on the server.

Three account types — patient, doctor and administrator — each see a different dashboard and can only perform the actions their role permits.

View the database ER diagram
  • IndexedDB object stores with indexes and relationships by ID
  • Doctors, patients, admins and medicines fetched from the course JSON server with fetch(), duplicate-safe
  • Create, read, update and delete across every clinical entity
  • PBKDF2-SHA256 password hashing via the Web Crypto API
  • AES-256-GCM encryption of sensitive fields at rest
  • Responsive layouts for desktop, tablet and mobile

Security by design

Controls implemented in this prototype, and the limits of what a browser-only application can guarantee.

Password protection

Passwords are salted and derived with PBKDF2-SHA256 (210,000 iterations). Plaintext is never stored or logged.

Data encryption

Addresses, NHS numbers, clinical notes and prescription instructions are encrypted with AES-256-GCM before storage.

Input validation

Email, password strength, NHS number, telephone and date of birth are validated before anything is saved.

Input sanitisation

User input is stripped of markup and rendered with textContent to prevent XSS and HTML injection.

IndexedDB storage

All clinical data lives in the browser's IndexedDB database ClinicalManagementDB.

Role-based access

Every dashboard page checks the session role and denies access to pages outside the user's permissions.

Important limitation. Client-side authorisation and browser-held encryption keys cannot protect real patient data. A production healthcare system requires server-side authentication, HTTPS/TLS, audit logging and a secured database server. See the README for the full analysis.
